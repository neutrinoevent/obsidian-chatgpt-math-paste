# ChatGPT Math Paste for Obsidian

Paste rendered ChatGPT responses into Obsidian without duplicated or broken
LaTeX. The plugin preserves inline math, display math, and the surrounding
Markdown formatting automatically.

> [!NOTE]
> This is an independent, open-source project. It is not affiliated with or
> endorsed by OpenAI or Obsidian.

## Why this exists

Rendered equations can carry several clipboard representations at once:

- accessible MathML text;
- the original TeX annotation; and
- visual HTML generated by KaTeX.

When that data is flattened into plain text, one equation can become two
adjacent, unusable copies:

```text
∣ψ⟩=…|\psi\rangle=\frac{1}{…}
```

ChatGPT Math Paste intercepts the paste while the rich clipboard structure is
still available. It extracts the original TeX and emits the delimiters Obsidian
expects.

## Features

- Converts rich KaTeX/MathML clipboard content into Obsidian Markdown.
- Emits `$...$` for inline equations and `$$...$$` for display equations.
- Removes duplicate accessible and visual equation renderings.
- Uses Obsidian's own HTML-to-Markdown converter for surrounding content.
- Converts plain Markdown `\(...\)` and `\[...\]` delimiters on paste.
- Avoids delimiter conversion inside inline code and fenced code blocks.
- Rewrites math commands Obsidian's renderer does not support into equivalents
  that it does, so pasted equations render instead of failing.
- Repairs math in notes that were already pasted, not only new pastes.
- Reports math commands that are known to be unrenderable and cannot be
  repaired automatically.
- Leaves ordinary clipboard content unchanged.
- Works without an API key, network access, telemetry, or external services.
- Supports Obsidian desktop and mobile according to the plugin manifest.

## Installation

### From a release archive

1. Download the `chatgpt-math-paste-<version>.zip` release archive from the
   [releases page](https://github.com/neutrinoevent/obsidian-chatgpt-math-paste/releases).
2. Verify the download against the accompanying `SHA256SUMS` release asset.
3. Create `<vault>/.obsidian/plugins/chatgpt-math-paste/`.
4. Extract `manifest.json` and `main.js` into that directory.
5. Reload Obsidian.
6. Open **Settings → Community plugins** and enable
   **ChatGPT Math Paste**.

Obsidian may hide `.obsidian` because it begins with a dot. Enable hidden files
in the operating system's file browser if necessary.

### Build from source

Requirements: Node.js 18 or newer and npm.

```bash
git clone https://github.com/neutrinoevent/obsidian-chatgpt-math-paste.git
cd obsidian-chatgpt-math-paste
npm ci
npm run check
```

Then copy the generated `main.js` and `manifest.json` into:

```text
<vault>/.obsidian/plugins/chatgpt-math-paste/
```

## Usage

With the plugin enabled, copy a ChatGPT response and paste it normally into an
Obsidian Markdown note. Automatic conversion runs only when recognized math is
present.

Two Command Palette actions are also available:

- **ChatGPT Math Paste: Normalize math delimiters in selection**
- **ChatGPT Math Paste: Normalize math delimiters in current note**

These commands convert `\(...\)` and `\[...\]` in existing Markdown. They do
not guess boundaries in text that was already flattened into duplicated
Unicode and TeX.

Two further commands work on notes that have already been pasted:

- **ChatGPT Math Paste: Fix math commands Obsidian cannot render in current
  note** — normalizes delimiters and rewrites unrenderable commands.
- **ChatGPT Math Paste: Report math commands Obsidian cannot render in current
  note** — lists commands this plugin knows Obsidian cannot render and cannot
  repair automatically.

## Settings

- **Convert math while pasting** — extracts TeX from rich clipboard HTML.
- **Normalize plain Markdown delimiters** — converts ChatGPT-style delimiters
  to Obsidian dollar delimiters.
- **Rewrite math for Obsidian's renderer** — converts commands MathJax cannot
  render into equivalents that it can. Disable to keep source TeX verbatim.
- **Show a notice after conversion** — displays a confirmation after the plugin
  handles a paste.

All conversion and notification settings are local to the Obsidian vault.

## How it works

The plugin listens to Obsidian's `editor-paste` event. When clipboard HTML
contains an `<annotation encoding="application/x-tex">` or
`application/x-latex` element, the converter:

1. reads the original TeX from the annotation;
2. determines whether the expression is inline or display math;
3. replaces the complete KaTeX/MathML wrapper with a temporary marker;
4. asks Obsidian to convert the remaining HTML to Markdown; and
5. replaces each marker with `$...$` or a `$$...$$` block.

If no supported math annotation is present, the rich HTML path returns without
interfering with Obsidian's normal paste behavior. The plain-text path only
takes over when it actually changes a recognized delimiter.

### Renderer compatibility

Extracting the original TeX faithfully is necessary but not sufficient.
ChatGPT renders math with KaTeX; Obsidian renders it with MathJax. KaTeX
defines commands that MathJax's default packages do not, so an equation can
survive the paste intact and still fail at render time, appearing as red
literal text inside a MathJax error box. `\oiint` is one such command.

The plugin therefore rewrites those commands into equivalents built only from
commands MathJax defines by default. The resulting note renders in a stock
vault with no plugin, preamble, or macro dependency, which is why the rewrite
happens at paste time rather than by extending MathJax at runtime.

The main implementation is split between:

- `src/main.ts` — Obsidian integration, settings, and commands.
- `src/converter.ts` — clipboard conversion and delimiter normalization.
- `src/tex-compat.ts` — the KaTeX-to-MathJax command tables and rewriting.
- `src/markdown-math.ts` — locating math regions in existing Markdown.
- `tests/` — regression coverage for each of the three modules above.

## Privacy and security

The plugin processes clipboard data only in memory during a user-initiated
paste. It does not:

- access or transmit note contents;
- access the filesystem directly;
- make network requests;
- invoke shell commands;
- use an OpenAI API key or any other credential; or
- collect analytics or telemetry.

The only persisted data is the plugin's three boolean settings, stored through
Obsidian's standard plugin settings API. See [SECURITY.md](SECURITY.md) for the
reporting policy and trust boundaries.

## Limitations

- Lossless recovery requires the original rich clipboard HTML or intact
  Markdown delimiters.
- Already-flattened duplicate text cannot be separated reliably in the general
  case. Re-copy the original response and paste with the plugin enabled.
- A future change to the source application's clipboard markup may require a
  new sanitized regression fixture.
- Clipboard behavior can differ between browsers, operating systems, and mobile
  applications. Please include that environment when filing an
  [issue](https://github.com/neutrinoevent/obsidian-chatgpt-math-paste/issues).
- The renderer compatibility table covers known gaps, not every possible one.
  A command that renders in ChatGPT but not in Obsidian and is absent from the
  table will still fail. Report it, and it becomes a table entry and a test.

## Development

```bash
npm ci          # reproducible dependency install
npm test        # run converter and rendering tests
npm run build   # type-check and create main.js
npm run check   # test, type-check, and build
```

Tests run in two layers. The converter suites check that the right strings are
produced. The rendering suite runs those strings through MathJax itself and
checks that they can actually be drawn: that every replacement renders, and
that composed symbols keep their ink inside their own box rather than painting
over neighbouring text. MathJax is a development dependency only; the plugin
still ships no runtime dependencies.

Generated `main.js`, dependencies, release archives, and operating-system
metadata are excluded from source control. A release archive contains the three
plugin files (`manifest.json`, `main.js`, and `versions.json`) together with the
public Markdown documentation and license.

### Adding a renderer compatibility entry

A command that renders in ChatGPT but not in Obsidian is fixed by one table
entry and one test:

1. confirm the failure in a scratch note; MathJax shows an undefined command
   as red text inside a box;
2. add the command to `MATHJAX_REPLACEMENTS` in `src/tex-compat.ts`, using
   only commands MathJax defines by default, or to `UNSUPPORTED_COMMANDS` if a
   single-token substitution cannot express it;
3. add a regression test in `tests/tex-compat.test.ts`, and, if the
   replacement is a composed symbol rather than a plain alias, a geometry
   assertion in `tests/mathjax-render.test.ts`; and
4. run `npm run check`, then verify the rendering in a vault.
